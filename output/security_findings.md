## Security Findings

| Severity | File:line | Finding | Suggested fix |
|---|---|---|---|
| P1 | src/auth/routes.py:10 | Hardcoded live API key in source: `API_KEY = "sk-live-4f9a8c7d2b1e4a6f9c3d5e7b8a0f1c2d"`. It is sent as a Bearer token on lines 72 and 96. | Load the key from an environment variable or secret manager (e.g., `os.environ["AUDIT_API_KEY"]`). Rotate the exposed key and remove it from git history. |
| P1 | src/auth/routes.py:40 | SQL injection via string formatting: `"FROM users WHERE username = '%s'" % username` (query built on lines 39-40, executed on line 41). | Use a parameterised query: `cur.execute("SELECT id, password_hash, salt, failed_attempts, locked_until FROM users WHERE username = ?", (username,))`. |
| P2 | src/auth/routes.py:22 | Weak password hashing: `return hashlib.sha256((salt + password).encode()).hexdigest()`. A single SHA-256 pass is fast and has no key-derivation work factor. | Use a password KDF such as bcrypt, scrypt, or argon2 (or `hashlib.pbkdf2_hmac` with a high iteration count) with a per-user random salt. |
| P2 | src/auth/routes.py:85 | Predictable session token: `token = hashlib.sha256(("%s:%s:%s" % (user_id, time.time(), salt)).encode()).hexdigest()`. It is derived from a known user ID, a timestamp, and a salt stored in the database. The raw token is also stored in plaintext on line 88. | Generate tokens with `secrets.token_urlsafe(32)`. Store only a hash of the token in the `sessions` table and compare hashes on lookup. |
| P2 | src/auth/routes.py:73 | Sensitive data sent to a third-party/external audit service: `json={"event": "login_failed", "user": username, "ip": client_ip}`. The same applies to line 97 for successful logins. | Minimise the payload (e.g., send a pseudonymous user ID instead of the username), confirm the data-sharing basis, and document the retention policy for the audit service. |
| P2 | src/auth/routes.py:28-29 | Missing input validation on user-controlled fields: `username = data.get("username")` and `password = data.get("password")` accept any JSON type (list, dict, number) and have no length limits before use. | Check that `username` and `password` are non-empty strings within a maximum length, and return 400 otherwise. |
